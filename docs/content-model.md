# 李娜静态网站内容设计

## 概述

本项目是一个以中国歌手李娜为核心的静态内容网站。当前最完整的数据资产是歌曲条目与曲谱图片，后续将逐步扩展到人物、专辑、年表、文章、视频与来源整理。

站点目标不是普通博客，而是一个可长期维护的资料站。内容组织应优先满足以下原则：

- 静态可构建：服务器只部署静态文件，不依赖数据库
- 内容可维护：数据文件尽量清晰、稳定、可人工编辑
- 结构可扩展：允许未来加入英文版、文章、人物、专题索引
- 展示与存储解耦：页面排序和聚合尽量在构建阶段完成，不把视图逻辑写死进单条内容

---

## 当前数据范围

当前已整理完成的核心内容：

- `songs`：242 首歌曲的结构化 JSON
- `scores`：与歌曲对应的本地曲谱图片

当前尚未正式落地但已经确定会加入的内容：

- `people`：人物资料，包括李娜、词作者、曲作者、合作歌手等
- `articles`：报道、采访、整理文、评论
- `timeline`：年表事件
- `albums`：专辑、精选集、影视原声、收录关系
- `sources`：资料来源与出处说明

---

## 当前目录结构

当前 `src/content` 下建议保持如下结构：

```text
src/
  content/
    songs/
      index.json
      青藏高原.json
      再梦一回.json
      ...
    scores/
      青藏高原/
        01.jpg
      再梦一回/
        01.jpg
      ...
```

目录职责：

- `src/content/songs/`
  保存所有歌曲条目。每首歌一个 JSON 文件，文件名与歌曲 `id` 一致。
- `src/content/songs/index.json`
  站点构建时使用的歌曲总索引。用于列表页、检索页、构建时预生成路由。
- `src/content/scores/<song-id>/`
  该歌曲对应的曲谱图片目录。图片文件名只保留页码，如 `01.jpg`、`02.jpg`。

## 歌曲数据模型

### 目标

歌曲 JSON 只描述歌曲自身，不保存贴吧采集过程信息，不保存排序信息，不保存无关来源痕迹。

### 当前推荐字段

```json
{
  "id": "青藏高原",
  "title": "青藏高原",
  "aliases": [],
  "work": {
    "category": "电视剧",
    "title": "天路",
    "usage": "主题曲"
  },
  "credits": {
    "lyricists": ["张千一"],
    "composers": ["张千一"],
    "translators": [],
    "arrangers": [],
    "performers": ["李娜"],
    "original_singers": []
  },
  "lyrics": {
    "language": "zh",
    "text": "..."
  },
  "scores": ["01.jpg"],
  "videos": [],
  "notes": []
}
```

### 字段说明

- `id`
  内容主键。必须稳定、唯一、可读。用于文件名、页面 slug、资源目录名。

- `title`
  主标题。默认用于页面标题、列表展示、站内检索。

- `aliases`
  别名列表。用于搜索命中、页面补充说明、重名区分。

- `work`
  歌曲所属作品或使用场景。
  当前字段：
  - `category`：如 `电视剧`、`电影`、`古典舞蹈`
  - `title`：作品名
  - `usage`：如 `主题曲`、`片头曲`、`片尾曲`、`插曲`

- `credits`
  创作与演唱关系。
  当前字段：
  - `lyricists`
  - `composers`
  - `arrangers`
  - `performers`
  - `original_singers`

- `lyrics`
  当前仅保留一种语言版本。
  当前字段：
  - `language`
  - `text`

- `scores`
  曲谱图片文件名数组，只写当前歌曲目录中的文件名，不写完整路径。
  页面渲染时根据 `id` 拼成：
  `src/content/scores/<id>/<filename>`

- `videos`
  视频外链数组。用于详情页嵌入或跳转。

- `notes`
  仅用于保存少量无法归入标准字段、但仍有价值的补充说明。

### 字段约束

- 没有值的字段应尽量省略，而不是写空对象或空字符串
- `scores` 只放文件名，不放完整路径
- `videos` 只放外链，不保存音频链接
- 不再保留 `catalog`、贴吧 `post_id`、采集楼层、原始文本等字段

## 命名与路径规范

### 歌曲文件

- 歌曲文件全部平铺在 `src/content/songs/`
- 文件名必须与 `id` 一致
- 文件扩展名统一为 `.json`

示例：

- `src/content/songs/青藏高原.json`
- `src/content/songs/再梦一回.json`
- `src/content/songs/贵妃醉酒-插曲.json`

### 曲谱图片

- 曲谱目录使用歌曲 `id`
- 图片文件名采用两位页码

示例：

- `src/content/scores/青藏高原/01.jpg`
- `src/content/scores/贵妃醉酒-插曲/01.jpg`
- `src/content/scores/当家谣/03.jpg`

### 重名消歧

如果歌曲标题重复，应优先用可读方式消歧：

1. 标题 + 作品名
2. 标题 + 用途
3. 标题 + 别名
4. 标题 + 序号

示例：

- `贵妃醉酒.json`
- `贵妃醉酒-插曲.json`

不建议使用随机 UUID 作为歌曲文件名或内容主键。

## 站点层面的分类目标

静态网站不应把“分类结果”全部写死进单条歌曲文件，而应在构建阶段根据字段生成不同索引页面。

当前可支持的分类维度：

- 按歌曲标题浏览
- 按首字或拼音浏览
- 按作品类型浏览
  例如 `电视剧`、`电影`
- 按作品名浏览
  例如某电视剧下的全部歌曲
- 按用途浏览
  例如 `主题曲`、`片头曲`、`插曲`
- 按词作者浏览
- 按曲作者浏览
- 按演唱者浏览
- 按是否带曲谱浏览
- 按是否带视频外链浏览

未来可补充的分类维度：

- 按年份
- 按专辑
- 按语言
- 按地区或题材
- 按合作人物

这些分类最好通过页面构建时动态生成，而不是写进歌曲 JSON。

## 后续建议的数据类型

为了支撑完整的网站，建议后续增加以下目录：

```text
src/content/
  songs/
  scores/
  people/
  albums/
  timeline/
  articles/
  sources/
```

### `people`

用途：

- 展示人物资料页
- 从人物页反向聚合其参与作品

建议字段：

- `id`
- `name`
- `aliases`
- `type`
- `bio`
- `tags`

### `albums`

用途：

- 展示专辑页
- 作为歌曲收录关系的聚合中心

建议字段：

- `id`
- `title`
- `year`
- `type`
- `summary`
- `cover`

### `timeline`

用途：

- 年表页
- 将歌曲、报道、事件统一串联

建议字段：

- `id`
- `year`
- `date`
- `title`
- `summary`
- `related_songs`
- `related_people`

### `articles`

用途：

- 长文页
- 报道、访谈、评论、专题整理

建议使用 `md` 或 `mdx`，而不是纯 JSON。

建议 frontmatter：

- `id`
- `title`
- `language`
- `date`
- `summary`
- `related_songs`
- `related_people`
- `sources`

### `sources`

用途：

- 保存资料出处
- 支撑以后对内容可信度和引用的管理

建议字段：

- `id`
- `title`
- `type`
- `url`
- `publisher`
- `date`
- `note`

## 页面目标

当前建议优先实现的页面：

- 首页
  展示李娜简介、代表作入口、内容导航

- 歌曲列表页
  从 `src/content/songs/index.json` 读取

- 歌曲详情页
  从单首歌曲 JSON 读取正文和曲谱

- 词作者索引页
  构建时聚合 `credits.lyricists`

- 曲作者索引页
  构建时聚合 `credits.composers`

- 作品索引页
  构建时聚合 `work.title`

第二阶段页面：

- 人物详情页
- 年表页
- 报道与文章页
- 专题聚合页

## 构建期数据处理建议

构建网站时，建议把“数据事实”和“页面派生数据”分开处理。

应保留在内容文件中的：

- 歌曲标题
- 别名
- 创作信息
- 歌词
- 曲谱文件名
- 视频外链

应在构建时动态推导的：

- 标题排序
- 首字分组
- 作者作品反查
- 作品聚合
- 有无曲谱、有无视频的筛选结果
- 相关文章与年表的反向关联

这样可以避免内容文件承担页面逻辑。

---

## 增量维护规则

后续新增歌曲时，应遵循以下流程：

1. 先确定歌曲 `id`
2. 在 `src/content/songs/` 新建对应 JSON
3. 如有曲谱，在 `src/content/scores/<id>/` 新建图片文件
4. 更新或重建 `src/content/songs/index.json`
5. 如有关联文章、人物、年表，再分别补充对应内容

不建议手工维护：

- 排序号
- 字母分类目录
- 复杂的页面聚合结果

这些都应由构建脚本或站点层逻辑自动生成。

---

## 当前结论

当前项目最适合的静态内容策略是：

- 歌曲 JSON 作为核心实体
- 曲谱图片按歌曲 `id` 归档
- 页面分类在构建期动态生成
- 后续逐步扩展人物、文章、年表与来源

这套方式既适合当前“先把李娜歌曲资料站搭起来”的目标，也能平滑扩展到以后更完整的中英双语资料网站。
